In short

audite-seu-claude is a small Python program that reads your Claude Code configuration (the CLAUDE.md file, skills, memories, plugins, and scripts) and flags instructions written for earlier models that now get in Claude Fable 5.2’s way. It is for people who use Claude Code every day and are switching models. It provides a report with charts and a list of suggestions; you choose what to approve, and your own Claude makes only those changes. All you need is Python 3: it uses no internet and does not change your configuration (it only saves the report where you tell it to).

What it is

The invisible legacy, found line by line

Anthropic published 10 points to watch for in Fable 5.2. It follows instructions literally, so old rules can have a different effect. This toolkit turns those 10 points into automated checks.

🔍 Finds what gets in the way

Requests for reasoning in the text (may trigger a refusal), “think less,” token budgets, instructions to always delegate, “never” without a reason, rigid style, outdated effort settings.

📊 Shows the impact

Charts by point and file, plus the weight of text included in every session: CLAUDE.md, the memory index, and skill descriptions. It also flags duplicate skills and old memories.

✅ You approve, Claude fixes

Select suggestions and generate correcoes.md. It becomes the change request: one item at a time, with a copy of the original. Security rules are never deleted.

How it works

Three steps, with you in the middle

The program only reads. You decide what changes; your Claude edits, and only what you approved.

varrer.py reads everything→ relatorio.html with charts→ you select what to approve→ correcoes.md→ “apply correcoes.md”→ run again and compare
Anthropic’s 10 points

What the official page says, and what the toolkit checks

Source: Prompting Claude Fable 5.2 (read on 11/11/2026). The figures come from Anthropic’s own tests.

1 Effort

The API default is high. Use medium for everyday work; xhigh and max only where you have measured a benefit. “Answer without thinking” does not reduce thinking: lower the effort setting. Checks: fixed max, xhigh as default, settings copied from an old model, Fable 5.2 set to low/medium.

2 Early stopping

On long tasks, it sometimes stops before finishing, especially at low and medium. The official text cut sessions abandoned midway in half, with +~30% more tokens. Checks: whether your CLAUDE.md contains this text (in blocos/terminar-tarefa.md).

3 Approvals

State the action (“yes, run the migration on the test database”) instead of saying “continue.” Approval rules should name the actions. Checks: approval for “any action” and claude -p "continue" in a script.

4 Code ownership

“This code is yours” makes it reorganize the code: ~1.5x more tokens and changes no one asked for. Use it only when you want that, and review the diff. Checks: the phrase, as a heads-up.

5 Silence

It works silently through long sequences. The official text makes it speak before the first tool call, with +~20% more tokens. Checks: whether you have this text (blocos/avisar-progresso.md).

6 Subagents

If the prompt says to delegate, it delegates a lot. Review these lines first. Checks: “always use subagents,” “agent army,” “delegate everything.”

7 Accumulated caution

Notes and memories accumulate “never” rules, and it follows them all. Remove those that have lost their reason; add scope and a reason to the others; list what does NOT need approval. Checks: “never” without a reason, “never try again,” absolute orders in all caps, old memories.

8 Outdated instructions

Remove: token budgets in prompts, “think less,” “treat the previous answer as final” (it stops pointing out its own mistakes), and rigid style rules. Checks: all four.

9 Final report

Ask it to write for someone who did not see the work: lead with the main point, without invented terms. Checks: whether you have this text (blocos/relatorio-claro.md).

10 Refusals

Asking it to write out its reasoning in the response can trigger the reasoning_extraction filter and stop the skill. Checks: “show your reasoning step by step,” “chain of thought” — high severity.

Prerequisites

Just Python 3 and git

No packages to install, no internet, no API key. Works on Linux, macOS, and WSL.

User guide · step by step

From clone to a corrected Claude

This is the order Anthropic recommends: adjust effort first, then clean up instructions, then measure.

1

Download the toolkit

One folder, one main file.

git clone https://github.com/inematds/audite-seu-claude.git ~/audite-seu-claude
2

Set Fable 5.2 to high for long tasks

The Claude Code /effort command changes the effort level (how much the model thinks); with no argument, it shows the current level. Use it before a large task. For agents running claude -p, pass --effort high.

/effort high
3

Run the audit

From inside the project folder. --home also reads your ~/.claude (global CLAUDE.md, skills, memories, plugins).

cd ~/meu-projeto
python3 ~/audite-seu-claude/varrer.py . --home --html relatorio.html --saida-json relatorio.json
# in the terminal: total findings, by point and severity
4

Open the report and select what to approve

Each suggestion has an ID (A001, A002…). Filter by layer — Fable 5.2 (lines that change the model’s behavior) or volume (context weight, duplicate or unused skills, old memories) — or by severity. Click generate correcoes.md: your browser downloads the file, and the text appears on screen. Move the file to the project folder. Or generate it right there in the terminal using the IDs:

python3 ~/audite-seu-claude/varrer.py --correcoes A001,A004,A007 --de relatorio.json --saida correcoes.md
5

Ask your Claude to apply the fixes

With correcoes.md in the project folder (you can also use the path: “apply ~/Downloads/correcoes.md”). The file header already explains how: one item at a time, a copy of the original in .audite-backup/, protected rules are never deleted, and plugin files are not edited. This counts as approval only for these edits.

# in Claude Code, in the project folder
apply correcoes.md
6

Run again and compare

Applied findings disappear. Then run your longest task and see where it stops, goes quiet, or delegates too much. For each symptom, paste in the right block from blocos/, one at a time.

python3 ~/audite-seu-claude/varrer.py . --home
cat ~/audite-seu-claude/blocos/terminar-tarefa.md # if it stops midway
7

Optional: the skill and CI

The skill performs steps 3 to 6 through Claude Code. --uso 30 reads your session logs (~/.claude/projects/*.jsonl, local) and flags skills you have not used in 30 days. --estrito fails CI if there is a high-severity finding.

cp -r ~/audite-seu-claude/skill/audite-seu-claude ~/.claude/skills/
python3 ~/audite-seu-claude/varrer.py . --home --uso 30
python3 ~/audite-seu-claude/varrer.py . --estrito  # exits with 1 if there is a "high" finding

Cautions and next steps

The auditor flags issues; you decide

Anthropic itself says that not every old instruction needs to go. Test each change on a real task of yours.

Protected
Security rules stayA “never” rule about APIs, credits, deleting, publishing, or passwords is marked as protected: the suggestion is to add scope and a reason, never to delete it.
Plugin
Do not edit plugin filesAn update will undo the change. Write in the global CLAUDE.md that the rule does not apply, or disable the plugin.
Cost
The blocks use tokensFinish the task: +~30% output. Progress updates: +~20%. Paste a block only if you see the symptom.
